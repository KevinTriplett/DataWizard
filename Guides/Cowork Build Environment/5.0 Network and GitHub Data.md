# 5.0 Network and GitHub Data

- **WebFetch rate-limits (HTTP 429).** Space calls out; lean on WebSearch snippets when throttled. (Source: Weave, 2026-06/08)
- **GitHub REST via web fetch is unreliable:** `api.github.com` returns empty content in some Cowork configurations, and unauthenticated REST shares a rate-limited egress (60/hr, often exhausted). Reliable paths, in order: `raw.githubusercontent.com` for file content (fetches even when the API is throttled), the repo's landing page for stars/forks/issues/license (tree and commit pages are robots-blocked for WebFetch - Community Stack, 2026-10), Chrome `get_page_text` on an org's `/repositories` page for listings, or a user-run `gh api ... | paste`. For file lists and file content of a public repo without the API, the jsDelivr mirror works: `https://data.jsdelivr.com/v1/packages/gh/<owner>/<repo>@<branch>?structure=flat` lists the files and `https://cdn.jsdelivr.net/gh/<owner>/<repo>@<branch>/<path>` reads one (Community Stack and DataWizard, 2026-10). For pulling a repo's files wholesale, a shallow `git clone --depth 1` beats fetching (see tools-research). (Source: VC S25; Weave, independent)

- **Some sandbox configurations 403-block `api.github.com` AND github.com HTML pages outright** (proxy-level), while GitHub release-asset downloads (`github.com/<org>/<repo>/releases/download/...`, including `checksums.txt`) and the git protocol still work. A pinned release-asset URL is then the reliable way to install a released binary: fetch the release's `checksums.txt` to discover exact asset names, download, verify sha256 locally. (Source: DW S329)
- **The container's GitHub API can refuse one repository with "access to this repository is not enabled for this session".** This is a per-session refusal, not a rate limit. Read the repository in the browser tools, or attach the repository to the session if the session has a tool for that. (DataWizard, 2026-10)
- **GitBook sources are agent-friendly:** append `.md` to any page URL for clean markdown; `llms.txt` is a full index; `?ask=` answers questions against the docs. (Source: Weave, 2026-06/08)
- **Filing GitHub issues via pre-filled `issues/new?title=&body=` URLs** (URL-encode the body, open in the user's authed browser, human submits) is a robust, low-brittleness alternative to JS form-filling -- and keeps the irreversible public action on a third party's repo in human hands. The `return_to` param survives a login redirect. (Source: DW S230)
- **API message responses can lead with `thinking` content blocks.** Reading `content[0].text` blindly fails when the first block is thinking-type; iterate the blocks and take the text-type ones. (DataWizard, 2026-09)
- **Overpass and Geofabrik: fetch from the device shell, not the container.** The container proxy refuses `overpass-api.de` and `download.geofabrik.de` (it passes raw.githubusercontent.com and the npm registry); `device_bash` reaches both - run the query there, write the result into a connected folder, and stage it in. Under load, one combined query with a small bbox per point succeeds where many per-point `around:` queries fail with 504 / 500, and mirror health flips within minutes; compute distances locally. Overpass mirrors do not help from the container: its proxy dropped the connection to `overpass-api.de` and an lz4 mirror, and other mirrors answered 500 or 504; the PDF Tools `fetch_pdf_from_url` on the Mac got HTTP 406, also with `Accept: */*`. Nominatim worked from the container. When the device shell was down, Claude in Chrome was the only path left: a `fetch` POST from a tab on `overpass-api.de` took 30-60 s per query and often returned 502. (LocationScout, 2026-10)
- **Overpass: tile large areas, and use `out geom;` for relations.** A query over one large bbox can return 504 on every public mirror while a 3 x 2 tile grid of the same area gets through; run one tile per `device_bash` call (30-90 s each - two tiles in one call hit the ~180 s cap, see Device Bridge), and when a tile keeps failing, reuse an earlier extract that covers the overlap instead of retrying. Ask for geometry with `out geom;`, not `out geom tags;`: the `tags` verbosity drops relation members, so multipolygon features such as large lakes disappear from the result with no error. After any extract, check feature counts by type before trusting it. (LocationScout, 2026-10)
