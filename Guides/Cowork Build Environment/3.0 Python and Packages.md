# 3.0 Python and Packages

- **`pip` has no package index from the sandbox in some configurations (HTTP 403).** numpy is typically preinstalled; graph/scientific extras (`networkx`, `igraph`, `scipy`) may not be installable. Hand-roll in numpy or write the script for local (native) execution. Packages installed on the user's machine are invisible -- the sandbox is an isolated Linux environment. (Source: Weave, 2026-06/08. Other configurations allow installs -- probe before planning around the restriction.)
- **A Mac virtualenv in a connected folder does not run in the device shell.** The device shell is a Linux VM, and `.venv/bin/python` is a symlink to the Mac interpreter, so the project's venv is dead there. To run a Python package from the computer, `tar` it without `.venv` into a connected folder, stage the tar, and build a fresh venv in the cloud container from the project's lock file (`requirements.lock`). The rebuilt venv reproduced the Mac outputs byte for byte. (Kosmosis, 2026-10)
- **System-wide `pip install --break-system-packages` can fail on an sdist in the container; a venv works.** Building a package from source with the system pip failed with `AttributeError: install_layout` (the distro's patched setuptools). A plain `python3 -m venv` plus `pip install <pkg>==<pinned version>` built the same package cleanly on Python 3.12 and 3.13. Build source-only packages inside a venv, never into the system Python. (Kosmosis, 2026-10)
- **`glob.glob()` order differs between the container and the Mac.** A page that embeds `{name: data-uri}` built from a glob is then not byte-reproducible across the two. Use `sorted(glob.glob(...))`. (LocationScout, 2026-10)
- **Rewriting a hand-compacted JSON file with `json.dump` reformats the whole file.** One-line rows exploded to many lines, so a 14-line change became a full-file diff. For small edits to a hand-formatted data file, use exact text replacement with a count assert, then `json.load` to validate. (LocationScout, 2026-10)
- **pipx with the newest Homebrew Python can fail to build packages that have C parts.** On the operator's Mac, with Python 3.15 as the newest Homebrew Python, a package with C parts and no wheel for that version (`yara-python`, and so GuardDog) failed to build. Install against an older interpreter: `pipx install --python /opt/homebrew/bin/python3.12 <pkg>`. (DataWizard, 2026-10)
- **A `re.sub` replacement-lambda's return value is literal.** Unlike a replacement *string*, a function's return is inserted verbatim - do not escape backslashes for it. Doubling them corrupted embedded JSON before a dry-run caught it. (DataWizard, 2026-09)
- **`str.lstrip("www.")` strips a character *set*, not a prefix** -- it corrupted `weave-...` to `eave-...` and silently poisoned dedup keys. Use `re.sub(r"^www\.", "", s)`. Dry-run-before-apply is what caught it. (Source: DW S224)
