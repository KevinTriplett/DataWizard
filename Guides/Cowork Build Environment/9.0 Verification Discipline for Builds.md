# 9.0 Verification Discipline for Builds

- **Minimum verification for a handoff = typecheck + build + smoke test.** Typecheck plus production build cannot catch runtime init failures; a headless jsdom component-init test reproduced an app black-screen in seconds. Include a mounted-component smoke test. (Source: VC S27)
- **The isolated `/tmp` verification loop:** copy the source minus `node_modules` to `/tmp`, `npm ci --ignore-scripts` (skip heavy binaries, e.g. `ELECTRON_SKIP_BINARY_DOWNLOAD=1`), then run tests + typecheck + build there. The host machine never runs unverified code, and its `node_modules` stays pristine. (Source: VC S28, S33)
- **Cloud-green is not host-green for environment-coupled globals.** A suite passing on the sandbox's Node can fail on the host's newer Node (e.g. Node 25+ ships built-in `localStorage` globals that shadow jsdom's in test workers). Verify env-coupled globals on the actual host runtime, not only in the cloud. (Source: VC S64)
- **Unit + component green is not app-works.** Hundreds of passing pure-function and component tests can coexist with an app that crashes on first real interaction, because nothing renders the real app against real state. Keep an integration/smoke tier that does. (Source: VC S62)
- **A fixture harness on a Mac fires real desktop notifications unless `osascript` is stubbed.** A script under test that calls `osascript -e 'display notification'` finds the real binary on macOS (the Linux VM has none, so cloud runs never show it): ~35 fixture scenarios produced ~35 live banners on the operator's screen. Put a stub `osascript` at the head of `PATH` before the first scenario (record calls to a file so a scenario can still assert a notification was attempted). Same class: scenarios that depend on a tool's *absence* must restrict `PATH` to system dirs, since the host machine may have the real tool (Homebrew `gh`). (Source: DataWizard, 2026-09)
- **Verify a GUI built against the mount by running it in the cloud sandbox under headless Chromium.** A stdlib web GUI (localhost server + embedded page) written to the user's vault cannot be seen from the sandbox (device VM localhost is not the sandbox's) and cannot be screenshotted from the device shell. Recipe that worked first time (DataWizard, 2026-09): copy the scripts plus a scratch db to a connected non-vault folder, `device_stage_files` them, run the server in the sandbox (`setsid nohup ... &`; `pkill` your own pattern kills the shell - see the SQLite section), drive it with Playwright (`chromium.launch({executablePath:'/opt/pw-browsers/chromium'})` - keyboard, selects, hover, colorScheme emulation) and `Read` the PNGs. Zero page errors in the console listener is the acceptance line; the screenshots go to the operator. Do the real first run on the operator's machine afterwards - the sandbox run proves the page, not the mount.
- **Playwright-vs-browser version mismatch in the sandbox: launch the headless shell by explicit path.** The npm `playwright` you install may expect a different Chromium build than the one preinstalled under `/opt/pw-browsers` (it then errors "Executable doesn't exist at .../chromium-<other>"), and the preinstalled full `chrome` binary has dropped `--headless=old`, so launching it directly fails with "Old Headless mode has been removed". Recipe that works: `find /opt/pw-browsers -name headless_shell` and pass that path as `executablePath` with `args:['--no-sandbox','--disable-gpu']`; the headless shell still implements the old headless mode Playwright drives. Never `pkill -f` a pattern that appears in your own command line - it kills the calling shell (exit 143/144); record PIDs and `kill` those. (Source: DataWizard, 2026-10) On the full `chromium` binary, `args:['--headless=new']` also works. (ReWoven, 2026-10)
- **A Playwright click near the fold can time out on unchanged page bytes.** Render metrics vary between container sessions: a ~20 px target below a 900 px fold failed Playwright's actionability check (click intercepted) on bytes that had passed before. `el.click()` on the element handle (inside the page, including a shadow root) is the robust form; keep tests away from fold-sensitive targets. (Holonic Canvas, 2026-10)
- **Chromium logs a console error for every 404 or 409 response and for any fetch from `file://`**, even when the page handles the response ("Failed to load resource: the server responded with a status of ..."). A "no console errors" acceptance line must allow exactly the lines the test provokes - matched by path and status, counted and asserted - and keep failing on anything else; avoid the `file://` error by not fetching on `file:`. (Holonic Canvas, 2026-10)
- **Headless Chromium in the container may not load Google Fonts.** For font-faithful test renders, install `@fontsource/<family>` with npm and inject its `@font-face` rules as data URIs at document level; document-level fonts also reach shadow roots. (ReWoven, 2026-10)
- **Consolidating a deck or document set: build a content inventory first.** A headless walk that opens every node and panel and dumps its text gives a complete inventory; exact duplicates can then be proved mechanically (`difflib` ratio 1.0) before a reviewer rules on merges. The same inventory is the reviewer's ground truth and, re-run after the build, the check that nothing was lost. The archive-side rule (the survivor must carry everything) is the Conventions Registry's "Consolidating to one home". (Evolutionary Media Commons, 2026-10)
- **Background test runs and source edits do not mix.** Suites started in the background kept running while the engine was being changed, so their results described a mix of versions. Stop them by pid before changing what they build. (Evolutionary Media Commons, 2026-10)
- **Timing-based Playwright checks become flaky when another agent runs Playwright on the same machine.** While a reviewer sub-agent tested in its own copy of the workspace and the main suites ran, two old, untouched checks failed once and passed on re-run (a light-theme colour sampled 1 unit off during a transition; a "dots never shift layout" check). Run timing-sensitive suites alone, and re-run a single failing check before calling it a regression. (Evolutionary Media Commons, 2026-10)
- **Browser Back in a test leaves the page when the app navigates with `history.replaceState`.** The journey steps replace history, so `page.goBack()` went to the previous document and the next `evaluate` hit a null element. Use an in-app move instead. (Evolutionary Media Commons, 2026-10)
- **Review an animation from a recorded video, not from paused stills.** Pausing all animations and stepping `currentTime` does not show animations that a promise or timer creates later (they never start while the others are paused). What worked: Playwright `recordVideo` on the context, then `ffmpeg -ss <end-1.75s> -vf fps=10-12` frames, composed into a strip with PIL. (Evolutionary Media Commons, 2026-10)
- **Verify your writes actually landed.** The recurring failure shape: an operation reports success but the work did not persist -- no push creds (commits never reach origin), `commit -am` skipping untracked files, stale-lock-blocked commits. Before trusting a git/build write: `git status -sb` (ahead/behind + untracked), `git fsck` (lock/object health), and confirm the push ran on the host. Mirrors Working Rule 5 and the MCP Reliability guide's verification protocol. (Source: VC S27-S34, cross-cutting)
